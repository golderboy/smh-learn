ขั้นตอน / หัวข้อ 1

เริ่มจากสิ่งที่ต้องเตรียม

คู่มือนี้เริ่มหลังติดตั้งระบบปฏิบัติการแล้ว เตรียมเครื่องเฉพาะสำหรับระบบ ไม่ใช้เครื่องที่มีฐานข้อมูลหน่วยงานอยู่แล้ว ผู้ติดตั้งต้องมีสิทธิ์ผู้ดูแลเครื่องและเชื่อมต่ออินเทอร์เน็ต หากยังไม่มีเครื่องหรือโดเมน ให้นำรายการนี้ให้เจ้าหน้าที่ IT เตรียมก่อน

สิ่งที่เตรียมทำอย่างไร
เครื่องเริ่มที่ CPU 4 แกน / RAM 8 GB / SSD 100 GB เป็นค่าจัดสรรเริ่มต้น ไม่ใช่ผลทดสอบผู้ใช้พร้อมกัน 1,000 คน
ชื่อเว็บไซต์เช่น learning.หน่วยงาน.org ให้ IT ตั้ง DNS ชี้มาที่เครื่อง ใช้ชื่อจริงแทน learning.example.org ในคำสั่ง
อีเมลผู้ดูแลใช้รับการแจ้งเตือนใบรับรอง เช่น admin@หน่วยงาน.org
IP ผู้ติดตั้งให้ IT ระบุ IP ที่เข้าถึงเครื่อง เพื่อเปิด HTTPS เฉพาะผู้ดูแลระหว่างเปลี่ยนรหัสแรก
สำรองข้อมูลมีที่เก็บนอกเครื่อง และผู้ถือกุญแจถอดรหัสสำรอง
สิทธิ์บัญชี Linux ที่ใช้ sudo ได้ หรือ Windows ที่เป็น Administrator
คำสั่งที่มี example.org และ 203.0.113.10 เป็นตัวอย่าง ต้องแทนค่าจริงก่อนกด Enter หากไม่มีโดเมนสาธารณะ ต้องใช้ใบรับรองขององค์กรโดยให้ IT ช่วยติดตั้ง ไม่เปิดใช้ Production ผ่าน HTTP

ขั้นตอน / หัวข้อ 2

รู้จักหน้าต่างพิมพ์คำสั่ง

  1. Linux ที่มีหน้าจอ: เปิดโปรแกรม Terminal หากเป็นเซิร์ฟเวอร์ให้ IT แจ้ง IP และชื่อบัญชี แล้วเปิด PowerShell บน Windows และพิมพ์ ssh ชื่อบัญชี@IPเครื่อง
  2. พิมพ์รหัส Linux แล้วกด Enter ระหว่างพิมพ์อาจไม่เห็นตัวอักษร นี่เป็นพฤติกรรมปกติ รหัส Linux คนละรหัสกับบัญชี admins ของเว็บไซต์
  3. คัดลอกคำสั่งหนึ่งกรอบ วางใน Terminal แล้วกด Enter รอจนมีบรรทัดให้พิมพ์คำสั่งใหม่ อย่าปิดหน้าต่างระหว่างติดตั้ง
  4. หากมี Error หรือสีแดง ให้หยุดขั้นนั้น เก็บข้อความเพื่อให้ IT ตรวจ ไม่ข้ามไปขั้นถัดไป
พิมพ์ใน Ubuntu / Linux
whoami
pwd
date

ผลที่ควรเห็น: เห็นชื่อบัญชี ตำแหน่งโฟลเดอร์ และวันเวลาที่ถูกต้อง

คัดลอก→วางใน Terminal→กด Enter→รอผล

ภาพอธิบายขั้นตอน ไม่ใช่ภาพหน้าจอของระบบปฏิบัติการ

คำว่า sudo หมายถึงทำงานด้วยสิทธิ์ผู้ดูแล คำว่า cd หมายถึงเข้าโฟลเดอร์ Docker คือโปรแกรมที่แยกเว็บ ฐานข้อมูล และบริการออกเป็นกล่องทำงาน คำว่า volume คือพื้นที่เก็บข้อมูลที่ยังอยู่เมื่ออัปเดตกล่อง

ขั้นตอน / หัวข้อ 3

ติดตั้งเครื่องมือใน AlmaLinux 9

ตรวจว่าเป็น AlmaLinux 9 ก่อน คำสั่งอ้างอิง Docker repository สำหรับ RHEL 9 และ AlmaLinux CRB/EPEL ยังไม่ได้ยืนยันจากการรันจริงบนเครื่อง AlmaLinux 9 การใช้ repository นี้อาศัยความเข้ากันได้กับ RHEL ให้ IT ตรวจแพ็กเกจเดิมก่อน ไม่ปิด SELinux

พิมพ์ใน AlmaLinux Terminal
cat /etc/almalinux-release
getenforce
sudo dnf install -y git python3 nginx firewalld openssl gnupg2 dnf-plugins-core policycoreutils-python-utils
sudo dnf config-manager --set-enabled crb
sudo dnf install -y epel-release certbot
sudo dnf config-manager --add-repo https://download.docker.com/linux/rhel/docker-ce.repo
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker run --rm hello-world
sudo docker compose version
sudo setsebool -P httpd_can_network_connect 1

ผลที่ควรเห็น: ระบบเป็นรุ่น 9, SELinux Enforcing, เห็น Hello from Docker! และ Docker Compose version

หากโปรแกรมติดตั้งแจ้งชนกับ Podman/Docker เดิม อย่าลบแพ็กเกจหรือข้อมูลเดิมเอง ให้ IT ตรวจบริการอื่นก่อน การเปิด httpd_can_network_connect ใช้ให้ Nginx ติดต่อ backend ไม่ใช่การปิด SELinux

ขั้นตอน / หัวข้อ 4

เปิด Firewall เฉพาะผู้ดูแลระหว่างตั้งต้น

ให้ IT ตรวจ SSH และ zone ก่อนเปิด Firewall เพื่อไม่ตัดการเชื่อมต่อ ใส่ IP จริงของผู้ดูแลแทน 203.0.113.10 ในบรรทัด rich-rule เปิด HTTP เฉพาะเพื่อขอใบรับรอง ยังไม่เปิดหน้า login ผ่าน HTTP

พิมพ์ใน AlmaLinux Terminal
sudo systemctl enable --now firewalld
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="203.0.113.10/32" port port="443" protocol="tcp" accept'
sudo firewall-cmd --reload
sudo firewall-cmd --list-all

ผลที่ควรเห็น: SSH ยังเข้าได้ เปิด 80 และเปิด 443 เฉพาะ IP ผู้ดูแล ต้องใช้ zone ที่ผูกกับ interface จริง หากมี IPv6 ให้ IT กำหนดนโยบายแยก

หลังเปลี่ยนรหัส admins ตรวจรับระบบ และ backup ผ่านแล้ว จึงเปิด HTTPS ตามนโยบายหน่วยงาน เครื่องที่ใช้ภายในอาจอนุญาตเฉพาะ subnet

พิมพ์ใน AlmaLinux Terminal
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload

ผลที่ควรเห็น: ผู้ใช้ที่องค์กรอนุญาตเข้าถึง HTTPS ได้ ทำขั้นนี้หลังตรวจรับและเปลี่ยนรหัสแรกเท่านั้น

ดาวน์โหลดรุ่น 1.0.0 และติดตั้งเว็บ

  1. แทน learning.example.org ด้วยชื่อเว็บไซต์จริงของหน่วยงาน ห้ามใส่ https:// หรือ / ต่อท้ายใน --domain
  2. คัดลอกคำสั่งแล้วรอ build อาจใช้เวลาหลายนาทีตามอินเทอร์เน็ต เมื่อจบต้องไม่มี Error
  3. เก็บ .env.production เป็นความลับ ไฟล์นี้มีรหัสฐานข้อมูลและกุญแจเข้ารหัส อย่าส่งลงแชตหรือ GitHub
พิมพ์ใน Ubuntu / Linux
sudo install -d -m 0750 -o "$USER" -g "$(id -gn)" /opt/smh-learn
git clone --branch v1.0.0 https://github.com/golderboy/smh-learn.git /opt/smh-learn
cd /opt/smh-learn
python3 scripts/setup-production.py --domain learning.example.org
chmod 600 .env.production
sudo sh scripts/install-production.sh

ผลที่ควรเห็น: เห็น production_http_verified: true และ Services started. มีฐานข้อมูลใหม่และบัญชี admins ไม่มีผู้ใช้/บทเรียนทดสอบ

พิมพ์ใน Ubuntu / Linux
dc() { sudo /usr/bin/docker compose --env-file .env.production -f compose.production.yaml "$@"; }
dc ps
dc exec -T nginx nginx -t

ผลที่ควรเห็น: บริการ app, nginx, mariadb, redis, queue-worker, scheduler ทำงาน และ nginx configuration test is successful

หากกลับมาทำต่อวันอื่นให้ cd /opt/smh-learn แล้วสร้าง dc() ใหม่ก่อนใช้คำสั่ง dc การติดตั้งซ้ำด้วย install-production.sh ใช้ข้อมูลเดิมและไม่รีเซ็ตรหัส ห้ามลบ .env.production หรือใช้ migrate:fresh / down -v

ขั้นตอน / หัวข้อ 6

ติดตั้งกุญแจ HTTPS ก่อนเข้าสู่ระบบ

HTTPS ทำให้เบราว์เซอร์แสดงการเชื่อมต่อปลอดภัย โดเมนต้องชี้เครื่องและพอร์ต 80 เข้าได้จากอินเทอร์เน็ตก่อนใช้ Let’s Encrypt ให้แทนค่าโดเมนและอีเมลในสองบรรทัดแรก หากเป็นระบบภายใน ให้ IT ใช้ใบรับรององค์กรแทนขั้นขอ Certbot

พิมพ์ใน Ubuntu / Linux
cd /opt/smh-learn
SMH_DOMAIN=learning.example.org
SMH_EMAIL=admin@example.org
sudo install -d -m 0755 /var/www/letsencrypt
sed "s/learning.example.org/$SMH_DOMAIN/g" docker/production/host-nginx.conf.example | sudo tee /etc/nginx/conf.d/smh-learning.conf >/dev/null
sudo nginx -t
sudo systemctl enable --now nginx
sudo certbot certonly --webroot -w /var/www/letsencrypt -d "$SMH_DOMAIN" --email "$SMH_EMAIL" --agree-tos --no-eff-email

ผลที่ควรเห็น: nginx -t ผ่าน และ Certbot แจ้งรับ certificate สำเร็จ ถ้าขอไม่ได้ให้หยุดและแก้ DNS/พอร์ต/อีเมลก่อน

พิมพ์ใน Ubuntu / Linux
sed "s/learning.example.org/$SMH_DOMAIN/g" docker/production/host-nginx-tls.conf.example | sudo tee /etc/nginx/conf.d/smh-learning.conf >/dev/null
sudo nginx -t
sudo systemctl reload nginx
curl -I "https://$SMH_DOMAIN/up"
sudo certbot renew --dry-run

ผลที่ควรเห็น: เว็บ /up ตอบ HTTP 200 และการจำลองต่ออายุผ่าน ห้ามกดข้ามคำเตือนใบรับรองบนเว็บ Production

ชุดทดสอบใช้ใบรับรองชั่วคราวกับ loopback เพื่อทดสอบ secure cookie เท่านั้น การออกและต่ออายุใบรับรองสาธารณะ ยังไม่ได้ยืนยันจากการรันจริง ต้องตรวจบนเครื่องขององค์กร

เข้าสู่ระบบครั้งแรกและนำเข้าข้อมูล

  1. เปิด Chrome หรือ Edge พิมพ์ https://ชื่อเว็บไซต์จริง/login ในช่องที่อยู่ด้านบน ไม่ใช่ช่องค้นหา
  2. บัญชีตั้งต้น username: admins รหัสแรก: P@ssw0rd112233 กดเข้าสู่ระบบ แล้วเปลี่ยนรหัสทันทีอย่างน้อย 10 ตัวอักษร หากเป็นการติดตั้งซ้ำให้ใช้รหัสล่าสุดของเจ้าของ
  3. เลือก ตั้งค่าเว็บไซต์ ปรับชื่อหน่วยงาน ภาพ และข้อความ จากนั้นเลือก นำเข้าข้อมูลพื้นฐาน
  4. ดาวน์โหลดเทมเพลตและนำเข้า แผนก → ตำแหน่ง → หมวด → ผู้ใช้ → ร้าน ตรวจตัวอย่างก่อนยืนยันทุกครั้ง
  5. ทำหลักสูตรทดสอบด้วยข้อมูลสมมติในฐานข้อมูลใหม่ เรียนจริงจนจบ และตรวจรายงานก่อนเปิดใช้จริง
เปิดภาพเพิ่มเติมของหัวข้อนี้

ผู้ใช้นำเข้าใหม่ username คือเลขประจำตัว รหัสแรก learn123456 บทบาทผู้เรียน บังคับเปลี่ยนก่อนใช้ เลขซ้ำถูกข้าม ไม่แทนข้อมูลเดิม ร้านที่นำเข้ายังรอ Admin อนุมัติ ดูคู่มือ Admin สำหรับขั้นตอนละเอียด

ตรวจผลก่อนเปิดใช้งานจริง

พิมพ์ใน Ubuntu / Linux
cd /opt/smh-learn
dc() { sudo /usr/bin/docker compose --env-file .env.production -f compose.production.yaml "$@"; }
dc exec -T app composer check-platform-reqs --no-dev
dc exec -T app php artisan ops:release-check --json

ผลที่ควรเห็น: platform ผ่าน, release-check ทุกข้อพร้อม และ ops:check ผ่าน รอ scheduler อย่างน้อยหนึ่งนาทีก่อนตรวจ TLS ต้องเป็น certificate เชื่อถือได้และเหลืออย่างน้อย 14 วัน

ขั้นตอน / หัวข้อ 9

สำรองข้อมูลและกู้คืนอย่างปลอดภัย

สำรองก่อนเปิดบริการ และทุกวันหลังเปิดใช้งาน คำสั่งนี้สร้างกุญแจครั้งแรกเพียงครั้งเดียว ห้ามสร้างทับกุญแจที่ใช้กับ backup เดิม ให้เจ้าหน้าที่ผู้รับผิดชอบเก็บสำเนากุญแจคนละที่กับไฟล์สำรอง

พิมพ์ใน Ubuntu / Linux
