ขั้นตอน / หัวข้อ 1

เริ่มจากสิ่งที่ต้องเตรียม

คู่มือนี้เริ่มหลังติดตั้งระบบปฏิบัติการแล้ว เตรียมเครื่องเฉพาะสำหรับระบบ ไม่ใช้เครื่องที่มีฐานข้อมูลหน่วยงานอยู่แล้ว ผู้ติดตั้งต้องมีสิทธิ์ผู้ดูแลเครื่องและเชื่อมต่ออินเทอร์เน็ต หากยังไม่มีเครื่องหรือโดเมน ให้นำรายการนี้ให้เจ้าหน้าที่ IT เตรียมก่อน

สิ่งที่เตรียมทำอย่างไร
เครื่องเริ่มที่ CPU 4 แกน / RAM 8 GB / SSD 100 GB เป็นค่าจัดสรรเริ่มต้น ไม่ใช่ผลทดสอบผู้ใช้พร้อมกัน 1,000 คน
ชื่อเว็บไซต์เช่น learning.หน่วยงาน.org ให้ IT ตั้ง DNS ชี้มาที่เครื่อง ใช้ชื่อจริงแทน learning.example.org ในคำสั่ง
อีเมลผู้ดูแลใช้รับการแจ้งเตือนใบรับรอง เช่น admin@หน่วยงาน.org
IP ผู้ติดตั้งให้ IT ระบุ IP ที่เข้าถึงเครื่อง เพื่อเปิด HTTPS เฉพาะผู้ดูแลระหว่างเปลี่ยนรหัสแรก
สำรองข้อมูลมีที่เก็บนอกเครื่อง และผู้ถือกุญแจถอดรหัสสำรอง
สิทธิ์บัญชี Linux ที่ใช้ sudo ได้ หรือ Windows ที่เป็น Administrator
คำสั่งที่มี example.org และ 203.0.113.10 เป็นตัวอย่าง ต้องแทนค่าจริงก่อนกด Enter หากไม่มีโดเมนสาธารณะ ต้องใช้ใบรับรองขององค์กรโดยให้ IT ช่วยติดตั้ง ไม่เปิดใช้ Production ผ่าน HTTP

ขั้นตอน / หัวข้อ 2

เปิด WSL2 บน Windows 11

  1. บันทึกงานและเตรียมรีสตาร์ตเครื่อง คลิก Start พิมพ์ PowerShell คลิกขวา Run as administrator แล้วกด Yes
  2. รันคำสั่งกรอบแรก รอจบ หากแจ้งให้ restart ให้รีสตาร์ต Windows แล้วเปิด PowerShell ตามปกติ
  3. ตรวจรายชื่อ Linux หากมี Ubuntu-24.04 ที่ใช้ระบบอื่นอยู่แล้ว อย่าติดตั้งทับ ให้ IT เตรียม Linux แยก คู่มือนี้ใช้ Ubuntu-24.04 สำหรับ SMH โดยเฉพาะ
  4. หลังติดตั้ง Ubuntu ครั้งแรก ตั้งชื่อ Linux เช่น smhoperator และรหัส Linux ของตัวเอง รหัสไม่แสดงขณะพิมพ์ เก็บไว้เพราะต้องใช้กับ sudo
พิมพ์ใน PowerShell (Run as administrator)
wsl --install --no-distribution
wsl --update

ผลที่ควรเห็น: WSL ติดตั้ง/อัปเดตแล้ว หากแจ้ง reboot ให้รีสตาร์ต

พิมพ์ใน PowerShell
wsl --set-default-version 2
wsl --list --verbose
wsl --install -d Ubuntu-24.04
wsl -d Ubuntu-24.04

ผลที่ควรเห็น: เปิด Terminal Ubuntu ได้ และ wsl --list --verbose แสดง VERSION 2

Windows→WSL2 Ubuntu→Docker Engine→SMH Learning

ภาพอธิบายขั้นตอน ไม่ใช่ภาพหน้าจอของระบบปฏิบัติการ

เส้นทาง Windows นี้ใช้ Linux ผ่าน WSL2 ไม่ใช่ XAMPP และไม่ต้องเปิด Docker Desktop integration ให้ distro เดียวกัน การเปิด WSL จาก Windows ที่ยังไม่เคยติดตั้งเลย ยังไม่ได้ยืนยันจากการรันจริงบนเครื่องใหม่

ขั้นตอน / หัวข้อ 3

ตรวจ systemd และเปิด Linux ค้างไว้

พิมพ์ใน Ubuntu / Linux
ps -p 1 -o comm=
cat /etc/os-release

ผลที่ควรเห็น: เห็น systemd และ Ubuntu 24.04 ถ้าเป็น systemd อยู่แล้วข้ามกรอบถัดไป

ถ้าไม่ใช่ systemd ให้ใช้ sudo nano /etc/wsl.conf อ่านไฟล์เดิมก่อน เพิ่มเฉพาะส่วน [boot] systemd=true ไม่ลบการตั้งค่าอื่น กด Ctrl+O → Enter → Ctrl+X แล้วกลับ PowerShell

พิมพ์ใน PowerShell
wsl --terminate Ubuntu-24.04
wsl -d Ubuntu-24.04

ผลที่ควรเห็น: เปิด Ubuntu ใหม่แล้ว ps -p 1 -o comm= เป็น systemd

ใช้ terminate เฉพาะ distro นี้ ห้าม wsl --shutdown เพราะหยุด Linux ทุกชุดรวมระบบเดิม จากการทดสอบ WSL อาจหยุดเมื่อไม่มี session เปิด แม้เปิด systemd แล้ว
พิมพ์ใน Ubuntu / Linux
sleep infinity

ผลที่ควรเห็น: คำสั่งไม่มีข้อความและรอค้าง ให้เปิดหน้าต่างนี้ไว้ เปิด PowerShell อีกหน้าต่างแล้ว wsl -d Ubuntu-24.04 เพื่อทำขั้นถัดไป

หากกด Ctrl+C หรือปิดทุกหน้าต่าง Ubuntu ระบบอาจหยุดและเว็บเข้าไม่ได้ สำหรับเปิดให้หน่วยงานใช้ตลอดเวลาให้ IT จัดการเริ่มงานตามบัญชี Windows และทดสอบหลังรีบูต/ออกจากระบบจริง การเริ่มอัตโนมัติและบริการ 24 ชั่วโมงบนเครื่องนี้ยังไม่ได้ยืนยันจากการรันจริง

ขั้นตอน / หัวข้อ 4

รู้จักหน้าต่างพิมพ์คำสั่ง

  1. Linux ที่มีหน้าจอ: เปิดโปรแกรม Terminal หากเป็นเซิร์ฟเวอร์ให้ IT แจ้ง IP และชื่อบัญชี แล้วเปิด PowerShell บน Windows และพิมพ์ ssh ชื่อบัญชี@IPเครื่อง
  2. พิมพ์รหัส Linux แล้วกด Enter ระหว่างพิมพ์อาจไม่เห็นตัวอักษร นี่เป็นพฤติกรรมปกติ รหัส Linux คนละรหัสกับบัญชี admins ของเว็บไซต์
  3. คัดลอกคำสั่งหนึ่งกรอบ วางใน Terminal แล้วกด Enter รอจนมีบรรทัดให้พิมพ์คำสั่งใหม่ อย่าปิดหน้าต่างระหว่างติดตั้ง
  4. หากมี Error หรือสีแดง ให้หยุดขั้นนั้น เก็บข้อความเพื่อให้ IT ตรวจ ไม่ข้ามไปขั้นถัดไป
พิมพ์ใน Ubuntu / Linux
whoami
pwd
date

ผลที่ควรเห็น: เห็นชื่อบัญชี ตำแหน่งโฟลเดอร์ และวันเวลาที่ถูกต้อง

คัดลอก→วางใน Terminal→กด Enter→รอผล

ภาพอธิบายขั้นตอน ไม่ใช่ภาพหน้าจอของระบบปฏิบัติการ

คำว่า sudo หมายถึงทำงานด้วยสิทธิ์ผู้ดูแล คำว่า cd หมายถึงเข้าโฟลเดอร์ Docker คือโปรแกรมที่แยกเว็บ ฐานข้อมูล และบริการออกเป็นกล่องทำงาน คำว่า volume คือพื้นที่เก็บข้อมูลที่ยังอยู่เมื่ออัปเดตกล่อง

ติดตั้งเครื่องมือใน Ubuntu 24.04

คำสั่งชุดนี้ทดสอบจริงใน Ubuntu 24.04.5 บน WSL2 ใช้ Docker Engine ภายใน Linux ไม่ต้องลง PHP, Node หรือ MariaDB บนเครื่อง host หากเครื่องมี Docker/Podman หรือบริการอื่นอยู่แล้ว ให้ IT ตรวจความเข้ากันได้ก่อน

พิมพ์ใน Ubuntu / Linux
sudo apt-get update
sudo apt-get install -y ca-certificates curl git python3 nginx openssl gnupg certbot
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

ผลที่ควรเห็น: ดาวน์โหลดเสร็จ ไม่มีข้อความติดตั้งล้มเหลว

พิมพ์ใน Ubuntu / Linux
sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<'EOF'
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: noble
Components: stable
Architectures: amd64
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo /usr/bin/docker run --rm hello-world
sudo /usr/bin/docker compose version

ผลที่ควรเห็น: เห็น Hello from Docker! และหมายเลข Docker Compose ใช้ชุดนี้กับ x86_64 / amd64 เท่านั้น

ดาวน์โหลดรุ่น 1.0.0 และติดตั้งเว็บ

  1. แทน learning.example.org ด้วยชื่อเว็บไซต์จริงของหน่วยงาน ห้ามใส่ https:// หรือ / ต่อท้ายใน --domain
  2. คัดลอกคำสั่งแล้วรอ build อาจใช้เวลาหลายนาทีตามอินเทอร์เน็ต เมื่อจบต้องไม่มี Error
  3. เก็บ .env.production เป็นความลับ ไฟล์นี้มีรหัสฐานข้อมูลและกุญแจเข้ารหัส อย่าส่งลงแชตหรือ GitHub
พิมพ์ใน Ubuntu / Linux
sudo install -d -m 0750 -o "$USER" -g "$(id -gn)" /opt/smh-learn

ผลที่ควรเห็น: เห็น production_http_verified: true และ Services started. มีฐานข้อมูลใหม่และบัญชี admins ไม่มีผู้ใช้/บทเรียนทดสอบ

เทียบผลติดตั้งกับภาพประกอบ

เมื่อคำสั่งติดตั้งจบ ให้ตรวจว่าบริการครบ 6 รายการ ชื่อบนเครื่องจริงอาจมีชื่อ project นำหน้า แต่คอลัมน์ Service ต้องเป็นชื่อเดียวกัน ใช้ dc ps เพื่อตรวจ

app/nginx/mariadb/redis ต้อง healthy ส่วน queue-worker และ scheduler ต้อง running และตรวจการทำงานจริงด้วย ops:check --queue ไม่ใช่ดูชื่อคอนเทนเนอร์เพียงอย่างเดียว

ภาพนี้ช่วยเทียบชื่อบริการ ขั้นนี้ยังไม่เปิดให้ทุกคนใช้ ต้องตั้ง HTTPS และเปลี่ยนรหัสแรกให้เสร็จก่อน

ขั้นตอน / หัวข้อ 8

เปิดเว็บบน Windows และเตรียมเครือข่าย

หลังติดตั้งเว็บและ HTTPS แล้ว เปิด Edge/Chrome บน Windows ด้วยชื่อโดเมนจริงที่ IT เตรียม WSL รองรับการเข้าถึง localhost จาก Windows แต่ยังต้องใช้ใบรับรองที่เชื่อถือได้สำหรับชื่อเว็บ อย่าเปิด Production ด้วย http://127.0.0.1:8080 เพราะ secure cookie ต้อง HTTPS

รูปแบบใช้งานสิ่งที่ต้องทำ
เครื่องเดียวให้ IT ตั้งชื่อเว็บใน DNS/hosts และใบรับรององค์กร แล้วใช้ HTTPS ตามชื่อจริง backendเปิด loopback8080
เครื่องอื่นใน LANให้ IT ตั้ง WSL networking/port forwarding และ Windows Firewall สำหรับ443 กับ IP/subnetที่อนุญาต WSL IPอาจเปลี่ยนหลัง restart
อินเทอร์เน็ตต้องมี DNS/router/firewall/certificateจริง ให้ IT รับผิดชอบก่อนเปิดผู้ใช้
เก็บไฟล์เก็บซอร์สใน /opt/smh-learn ของ Linux ไม่ใช้ /mnt/c สำหรับฐานข้อมูลหรือ Docker data

การทดสอบรอบนี้เข้าผ่าน https://127.0.0.1:18443 ด้วยใบรับรองชั่วคราวเฉพาะชุดทดสอบ และผ่าน native Docker ใน WSL ไม่ได้ทดสอบ LAN/Internet/Windows Firewall จริง ดู Microsoft WSL Networking สำหรับ topology ของเครื่ององค์กร

ขั้นตอน / หัวข้อ 9

ติดตั้งกุญแจ HTTPS ก่อนเข้าสู่ระบบ

HTTPS ทำให้เบราว์เซอร์แสดงการเชื่อมต่อปลอดภัย โดเมนต้องชี้เครื่องและพอร์ต 80 เข้าได้จากอินเทอร์เน็ตก่อนใช้ Let’s Encrypt ให้แทนค่าโดเมนและอีเมลในสองบรรทัดแรก หากเป็นระบบภายใน ให้ IT ใช้ใบรับรององค์กรแทนขั้นขอ Certbot

พิมพ์ใน Ubuntu / Linux
cd /opt/smh-learn
SMH_DOMAIN=learning.example.org
SMH_EMAIL=admin@example.org
sudo install -d -m 0755 /var/www/letsencrypt
sed "s/learning.example.org/$SMH_DOMAIN/g" docker/production/host-nginx.conf.example | sudo tee /etc/nginx/conf.d/smh-learning.conf >/dev/null
sudo nginx -t
sudo systemctl enable --now nginx
sudo certbot certonly --webroot -w /var/www/letsencrypt -d "$SMH_DOMAIN" --email "$SMH_EMAIL" --agree-tos --no-eff-email

ผลที่ควรเห็น: nginx -t ผ่าน และ Certbot แจ้งรับ certificate สำเร็จ ถ้าขอไม่ได้ให้หยุดและแก้ DNS/พอร์ต/อีเมลก่อน

พิมพ์ใน Ubuntu / Linux
sed "s/learning.example.org/$SMH_DOMAIN/g" docker/production/host-nginx-tls.conf.example | sudo tee /etc/nginx/conf.d/smh-learning.conf >/dev/null
sudo nginx -t
sudo systemctl reload nginx
curl -I "https://$SMH_DOMAIN/up"
sudo certbot renew --dry-run

สำรองข้อมูลและกู้คืนอย่างปลอดภัย

สำรองก่อนเปิดบริการ และทุกวันหลังเปิดใช้งาน คำสั่งนี้สร้างกุญแจครั้งแรกเพียงครั้งเดียว ห้ามสร้างทับกุญแจที่ใช้กับ backup เดิม ให้เจ้าหน้าที่ผู้รับผิดชอบเก็บสำเนากุญแจคนละที่กับไฟล์สำรอง

พิมพ์ใน Ubuntu / Linux
cd /opt/smh-learn
sudo install -d -m 0700 /etc/smh-learning
sudo test ! -e /etc/smh-learning/backup.pass && sudo sh -c 'umask 077; openssl rand -base64 48 > /etc/smh-learning/backup.pass'
sudo python3 scripts/backup-production.py --passphrase-file /etc/smh-learning/backup.pass
dc exec -T app php artisan ops:check --queue --backup --json

ผลที่ควรเห็น: เห็น verified: true และไฟล์เข้ารหัส .tar.gz.gpg กับ .json ใน .backups ขณะสำรองเว็บพักชั่วคราวแล้วเปิดกลับพร้อม worker

พิมพ์ใน Ubuntu / Linux
sudo install -m 0644 docker/production/smh-backup.service docker/production/smh-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now smh-backup.timer
sudo systemctl list-timers smh-backup.timer

ผลที่ควรเห็น: เห็นเวลาสำรองรายวัน ตรวจ timedatectl ให้ตรงเวลา Asia/Bangkok

ส่งสำเนา .tar.gz.gpg และ .json ออกนอกเครื่องตามนโยบาย IT กำหนดการเก็บย้อนหลังเอง โปรแกรมไม่ลบไฟล์เก่าให้ การมี verified หมายถึงเข้ารหัสและตรวจไฟล์แล้ว ต้องทดสอบกู้คืนด้วย

กู้คืนในระบบแยกเท่านั้น เปิดเอกสาร PRODUCTION_OPERATIONS.md และทำตาม restore-production.py โปรแกรมปฏิเสธฐานข้อมูลที่ไม่ว่าง การกู้คืนจริงที่ใช้ข้อมูลใหม่แล้วต้องให้เจ้าของข้อมูลตัดสินใจ ห้ามผู้เริ่มต้นใช้ down -v / migrate:fresh เพื่อแก้ปัญหา
