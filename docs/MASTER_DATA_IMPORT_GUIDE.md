# นำเข้าข้อมูลพื้นฐานและบัญชีตั้งต้น — รุ่น 1.0.0

เข้าระบบผ่าน `/login` แล้วเลือก **บริหารระบบ → นำเข้าข้อมูลพื้นฐาน** (`/admin/imports`) ผู้ใช้ต้องมีบทบาทผู้ดูแลระบบและสิทธิ์นำเข้าพร้อมสิทธิ์จัดการหัวข้อนั้น

## ลำดับการนำเข้า

1. นำเข้าแผนกและตำแหน่งก่อน หากผู้ใช้มีการระบุรหัสข้อมูลอ้างอิง
2. เลือกหัวข้อแล้วดาวน์โหลดเทมเพลต Excel จากหน้านำเข้า
3. กรอกชีต `Data` ตั้งแต่แถวที่ 2 คงชื่อคอลัมน์เดิม ชีตคำแนะนำมีตัวอย่างที่ไม่ถูกนำเข้า
4. อัปโหลด `.xlsx` ไม่เกิน 10 MB / 1,000 รายการ กด **ตรวจไฟล์และแสดงตัวอย่าง**
5. ตรวจจำนวนเพิ่มใหม่/ข้ามรายการซ้ำ และแถว Excel ก่อนกด **ยืนยันนำเข้า** ตัวอย่างมีอายุ 30 นาทีและใช้ได้เฉพาะผู้ตรวจไฟล์

| หัวข้อ | คอลัมน์ |
| --- | --- |
| แผนก | รหัสแผนก, ชื่อแผนก |
| ตำแหน่ง | รหัสตำแหน่ง, ชื่อตำแหน่ง |
| หมวดหลักสูตร | รหัสหมวด, ชื่อหมวด, คำอธิบาย (เว้นว่างได้) |
| ผู้ใช้ | หมายเลขประจำตัว, รหัสบุคลากร, ชื่อ, นามสกุล, รหัสแผนก, รหัสตำแหน่ง, อีเมล, โทรศัพท์, ประเภทบุคลากร |
| ร้านสวัสดิการ | รหัสร้าน, ชื่อร้าน, ข้อมูลติดต่อ (เว้นว่างได้) |

หมายเลขประจำตัวต้องเป็น **ข้อความตัวเลข 1–15 หลัก** คอลัมน์รหัสและโทรศัพท์ในเทมเพลตตั้งเป็น Text เพื่อรักษาเลขศูนย์นำหน้า หากนำข้อมูลจากไฟล์อื่นมาให้ใช้ Paste Values และตรวจรูปแบบเซลล์ก่อนบันทึก ไม่รับสูตร Macro หรือลิงก์ภายนอกใน workbook

ผู้ใช้ต้องมีหมายเลขประจำตัว ชื่อ และนามสกุล รหัสบุคลากรเว้นว่างได้ ระบบใช้หมายเลขประจำตัวแทน คอลัมน์อื่นเว้นว่างได้ หากระบุแผนก/ตำแหน่งต้องใช้รหัสที่เปิดใช้งานในระบบ

เลขประจำตัวที่มีอยู่แล้วหรือซ้ำกับแถวก่อนหน้าในไฟล์จะถูกข้าม **ไม่แก้ข้อมูล รหัสผ่าน หรือบทบาทของบัญชีเดิม** รายการใหม่ได้รับบทบาทผู้เรียนเท่านั้น รหัสผ่านแรก `learn123456` และต้องเปลี่ยนก่อนใช้งาน รหัสบุคลากรหรืออีเมลของคนใหม่ที่ชนกับคนอื่นจะแจ้งให้แก้ไฟล์ ส่วนข้อมูลพื้นฐานชนิดอื่นไม่เขียนทับรหัสเดิม

ข้อมูลที่ไม่ถูกต้องทำให้ยังบันทึกไม่ได้ ระบบตรวจซ้ำภายใน transaction ก่อนบันทึก หากมีข้อผิดพลาดจะไม่เกิดการนำเข้าเพียงบางส่วน การกดยืนยันซ้ำด้วยรายการเดิมไม่สร้างข้อมูลซ้ำ ตัวอย่างผู้ใช้เข้ารหัสในฐานข้อมูล หลังบันทึกล้างรายละเอียดตัวอย่างและเก็บ audit เฉพาะชนิดข้อมูล จำนวน และ hash ของไฟล์ ตัวอย่างที่หมดอายุจะถูกเก็บกวาดรายชั่วโมง

ร้านที่นำเข้ามีสถานะ **รออนุมัติ** และไม่มีผู้ปฏิบัติงาน ให้กำหนดคนจากเมนูร้านและคูปอง แล้วให้แอดมินอนุมัติก่อนรับคูปอง Excel ไม่ให้สิทธิ์ผู้คุมหมวดหรือร้านโดยอัตโนมัติ

## แอดมินตั้งต้น

`DatabaseSeeder` สร้างบัญชี `admins` รหัสผ่านแรกตามที่เจ้าของระบบกำหนด (`P@ssw0rd112233`) บังคับเปลี่ยนรหัสผ่านก่อนใช้งาน หลังเปลี่ยนแล้ว seeder ไม่รีเซ็ตหรือเขียนทับบัญชีนี้ บัญชีตั้งต้นได้รับสิทธิ์บริหารระบบครบและมีตัวระบุสงวนที่ unique ในฐานข้อมูล

ทุกบัญชีรวมถึงแอดมินรองแก้ชื่อ เลขประจำตัว บทบาท สถานะ หรือรีเซ็ตรหัสของบัญชีตั้งต้นผ่านระบบไม่ได้ เจ้าของบัญชีเปลี่ยนรหัสผ่านของตัวเองจากเมนูบัญชีได้ แอดมินรองสร้างได้หลายคนโดยกำหนดบทบาทผู้ดูแลระบบในหน้าบัญชีบุคลากร

## นำเข้าข้อสอบใหม่

หน้าจัดการหลักสูตร → นำเข้าข้อสอบ มีปุ่ม **ดาวน์โหลดเทมเพลตข้อสอบ Excel** รองรับปรนัย 4–6 ตัวเลือก เลือกถูกเพียงข้อเดียว ค่าจำนวนครั้ง Posttest ตั้งจากรอบเรียนในระบบ

ปุ่ม **ล้างข้อสอบเดิมเพื่อนำเข้าใหม่** ใช้กับเวอร์ชันร่างที่ชุดสอบยังเป็นร่างและไม่เคยมีการสอบ จะล้าง Pretest/Posttest ของเวอร์ชันนั้นและยกเลิกตัวอย่างนำเข้าเดิม จากนั้นนำเข้าไฟล์เดิมหรือไฟล์ใหม่ด้วยรหัสข้อเดิมได้

หากเผยแพร่หรือมีประวัติสอบแล้ว ให้สร้างเวอร์ชันใหม่ก่อนล้าง ชุดสอบและคำตอบของเวอร์ชันเดิมเก็บไว้ครบ ข้อสอบเดิมถูกเก็บเป็นรายการที่เลิกใช้งานและยังรักษารหัส/เฉลยเดิม ไม่ลบหลักฐานผลสอบ

## เตรียม Production

metadata ของแอปเป็นรุ่น `1.0.0` หน้าเว็บใช้ Cobalt Coral และข้อความทั่วไป การจัดข้อความในฐานข้อมูลปัจจุบันใช้ `app:prepare-release-text` ตรวจรายการ และ `--apply` แก้เฉพาะข้อความที่ตรงกับรายการเดิมที่ระบุไว้ ไม่มีการลบข้อมูลหรือเปลี่ยนรหัสอ้างอิง สื่อ ประวัติเรียน/สอบ แต้ม คูปอง และใบสรุปส่งเบิกอยู่ครบ

ข้อมูลจำลองยังมีตัวบ่งชี้ `is_demo` อยู่ตามเดิม แม้ปรับข้อความที่แสดงแล้ว จึงต้องใช้ฐานข้อมูลและการตั้งค่าของ Production แยกตาม `PRODUCTION_DEPLOYMENT_CHECKLIST.md` ไม่ยกบัญชีจำลองขึ้นใช้งานจริง โครง ThaiD ยังปิดจนกว่าจะทดสอบกับองค์กรและเซิร์ฟเวอร์จริง
